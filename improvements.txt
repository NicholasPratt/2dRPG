# Core Architecture & Action Plan: 2D RPG Engine & Editor

This project uses a hybrid screen pipeline:

- Runtime visuals are pre-baked per-screen PNGs exported by Wall/Floor Paint: `<mapId>_floor.png`, `<mapId>_wall.png`, and `<mapId>_preview.png`.
- Runtime structure remains `.admap` data: three tile layers, with layer 1 currently acting as the solid collision/wall-guide layer.
- The `.admap v4` collision-bitmask migration should be deferred until gameplay needs explicit transparent-object or interaction flags. Removing the current floor/ceiling tile layers now would break active editor workflows.

## Implemented Runtime Foundation

The codebase now has runtime-facing loaders for:

- `.adchapter`: `src/game/chapter.*`
- `.admap`: `src/game/map.*`
- `.adpath`: `src/game/path.*`
- `.sprite.json`: `src/game/sprite.*`
- `.tileset.json`: `src/game/tileset.*`

`adventure_game_window` provides a GLFW/OpenGL runtime shell with:

- Fixed 60 Hz update loop.
- Chapter start-screen loading.
- Floor/wall PNG rendering from `assets/game/tilesets/`.
- Basic player movement and mid-layer tile collision.
- Screen-link transitions when crossing screen bounds.
- Runtime path entities moving along `.adpath` waypoints.

## Remaining Priorities

1. Replace fixed-pipeline OpenGL with a shader/core-profile renderer.
2. Add character save/load and connect runtime sprites to loaded `.sprite.json` metadata.
3. Persist defeated-enemy state per screen/chapter.
4. Add a deliberate `.admap v4` migration only when transparent/interactable collision flags are needed.
